# 星纪

**在线体验**：https://amandaji777-lgtm.github.io/CinfinityX3416/ （GitHub Pages，跟这个分支同步更新，可以直接在手机浏览器打开、加到主屏幕安装成 PWA）

一个手机端小工作台，核心是四块：**AI 对话**（含完整资料库/长记忆/主动消息）、**记忆收藏**、**能量波动（心情颜色记录）**、**日历备注**。纯前端 PWA，不需要自己的服务器，数据全部存在你手机/电脑浏览器本地。

## 这是什么、不是什么

这不是完整版指令里那个大而全的"个人成长 × 特殊情感连接工作台"——没有任务管理、项目管理、知识库、日程、学习记录、财务记账、每日复盘、特殊连接日记、链接星图、字卡这些模块。

AI 对话部分保留了完整的资料库体系（对方角色卡/我的角色卡/预设/世界书/手工长记忆五个独立区域）、独立长记忆自动总结、角色主动消息、多供应商协议（OpenAI 兼容 / Anthropic / Gemini / 自定义协议映射），以及第 5 部分的"每日链接状态"。这几块本身就是相对独立、自成一体的功能，即使你不用也不会拖累其他功能，所以按原样保留下来。

## 快速开始

这是纯静态网页，不需要构建：

1. 用任意静态服务器打开 `index.html`，例如：
   ```
   python3 -m http.server 8000
   ```
   然后浏览器访问 `http://localhost:8000`。
2. 或者直接部署到 GitHub Pages / Vercel / Netlify 等静态托管。
3. 打开直接进入主界面，不用先过一遍设置流程；工作台名称、主题这些随时可以在"更多 → 工作台设置"里改。

## ⚠️ 预览地址、安装与数据不是一回事

- 用普通浏览器标签页打开只是"预览"，不是稳定使用方式。
- 请在手机浏览器里把网页"添加到主屏幕"（iPhone Safari 用分享按钮里的"添加到主屏幕"；Android Chrome 会提示"安装应用"），这样才是真正安装成 PWA。
- **更换浏览器、清理网站数据、卸载这个 PWA、或者预览域名发生变化，都可能导致本地数据再也打不开**。这不是 bug，是浏览器本地存储的固有特性。
- 应对办法只有一个：**定期备份**。

## 如何备份 / 换设备

1. 打开"更多 → 数据与备份 → 立即备份（导出 JSON）"，会下载一个 `shiguang-backup-*.json` 文件，请自己保存好（网盘、邮件发给自己都行）。
2. 换设备或者数据丢失后，打开新环境的应用，"更多 → 导入备份恢复"，选中刚才的 JSON 文件即可。
3. **备份文件不包含任何 API Key**（这是刻意设计，避免密钥随备份到处流转），恢复后需要重新在"更多 → API 连接"里填一次密钥。
4. 建议每次做重要记录后，或者升级应用前，都手动备份一次。

## AI 对话怎么配置

1. 打开"更多 → API 连接 → ＋ 添加连接"。
2. 可以选预设（OpenAI / DeepSeek / xAI Grok / Anthropic / Gemini）自动填好地址和常用模型名，也可以完全自定义。
3. 填入你自己的 **API Key**（不是网页会员密码）。
4. 点"测试"，如果失败会告诉你具体原因（401 密钥错、404 地址错、429 限流或欠费、CORS/网络问题等）。
5. 回到"Home"标签页，先去"AI 资料库"（对话列表右上角的玫瑰图标）建好想用的角色卡等资料，再新建对话绑定连接和资料，就能聊天了。

### 支持的协议

- **OpenAI 兼容**：OpenAI、DeepSeek、xAI Grok 及各种中转服务，只要接口形状是 `/chat/completions`。
- **Anthropic**：官方 Messages API。
- **Gemini 原生**：Google 的 `generateContent` / `streamGenerateContent` REST 接口。
- **自定义协议映射**：给还没适配的服务商用。可以自己填请求方法、URL、鉴权头、请求体模板（`{{model}}` `{{apiKey}}` `{{system}}` `{{messagesJSON}}` 等占位符做字符串替换）、响应文本路径（如 `choices.0.delta.content`）和流式格式。这套映射只做声明式的字段替换，**不会执行任何你或对方返回的代码**，所以有一些边缘情况的协议可能套不进去——如果套不进去，通常还是得自己写个小后端转换一下。

### 网页会员 ≠ API Key

ChatGPT Plus、Claude Pro、Gemini Advanced、Grok 网页会员这些订阅，**通常不能**直接当 API Key 用。你需要去对应厂商的"开发者平台 / API 控制台"单独申请密钥、单独计费。如果不确定，去对应厂商官网搜索"API key"或"开发者平台"。

### 为什么某些服务商必须自建后端 / Relay

浏览器出于安全策略，很多 API 服务商不允许网页直接跨域调用（CORS），也没法真正把密钥"藏起来"。如果测试连接一直提示网络/CORS 错误，通常意味着这家服务商不支持浏览器直连，需要你自己搭一个简单的中转后端（Serverless Relay）来转发请求。这个应用本身不会、也不能绕过浏览器的安全限制。

### 密钥安全性

API Key 用浏览器内置的 Web Crypto（AES-GCM）加密后存在本地 IndexedDB 里，不会出现在源码、日志或备份文件中。但这仍然是"前端能做到的最好程度"，不是绝对安全——如果你很在意，请优先使用自己的安全后端中转，而不是在前端直接填生产环境的重要密钥。

## 功能怎么用

### AI 资料库（对话列表右上角的玫瑰图标）
五个独立区域：**对方角色卡 / 我的角色卡 / 预设 / 世界书 / 手工长记忆**。落地页是五个分区各一行，点进去才是该分区自己的独立页面（整页抽屉、带返回按钮），不是切标签页。每个区域都能：
- **文字新建**：逐项填写（每个字段都是原指令列出的那些，比如角色卡的姓名/外貌/边界/语言风格等），或者切换成"整段粘贴"模式直接丢一段自然语言描述进去——缺什么字段就空着，系统不会替你编。填完都会先给你看一遍转换后的 JSON 预览，确认了才保存。
- **编辑 / 复制 / 导出 JSON / 上传 JSON 导入**：导入时会先给预览，确认了才真正存进去，不会自动塞错区域。
- 世界书是"多条目"的：每条目有标题、正文、常驻/关键词触发、关键词、优先级、插入位置等。

新建对话时，从这五个区域里挑：对方角色卡（0-1）、我的角色卡（0-1）、预设（0-1）、世界书（0-多）、手工长记忆（0-多），再选一个聊天用的 API 连接。

### 上下文是怎么拼起来发给 AI 的
顺序固定为：事实与边界 → 预设 → 对方角色卡 → 我的角色卡 → 常驻世界书 → 命中关键词的世界书条目 → 手工长记忆 → 自动长记忆（第8部分）→ 最近聊天记录 → 你刚发的消息 → 预设里的"历史后提示"。聊天室里点"本轮上下文预览"可以展开看到组装后的完整文本（不会显示密钥）。

### 独立长记忆（对话设置里）
和上面手工长记忆不是一回事——这个是**自动**的：可以配置一个专门做总结的连接（不填就用聊天连接本身），设置"每 N 条消息自动总结一次"或手动点"立即总结"，AI 会从最近的对话里只提取稳定偏好、重要信息、重要事件、关系变化、约定和禁忌，不会编造。生成的记忆默认是"待确认"状态，需要你在"查看/管理长记忆"里手动确认、编辑、停用或删除后，才会被后续对话真正引用。回溯编辑/让他重说导致的消息被封存时，相关联的记忆会自动标记为"已停用"（不是删除，可以恢复）。

### 角色主动消息（对话设置里，默认关闭）
角色可以"主动"找你说话，但**如实说明能力上限**：这个应用没有独立的后台服务或推送通道，所以只会在你打开 App、切回前台、或者 App 保持打开期间的定时检查里生成，**应用被彻底关闭后不会有任何推送**。三种模式：关闭 / 仅生成草稿等你确认发送 / 允许直接自动发送。触发机制是"随机检查 + 条件评分 + 冷却保护"，不是固定间隔——评分会参考距离上次聊天多久、是不是像还没聊完、收藏了多少条这个对话的内容，再加上一点随机性，绝不会用愧疚、威胁或道德绑架的话术。可以设安静时段、最短冷却分钟数、每日上限，还有一键暂停。

### 每日链接状态（AI 资料库 → 对方角色卡 → 每日链接状态）
给每个角色，每天手动记一条：活跃 / 平静 / 偏弱，加上判断依据和睡眠/身体/情绪/压力/环境这些参考信息。统计只会告诉你"过去 30 天里活跃了几天、平静了几天"，**不会替你断言这代表什么因果关系或链接真伪**，纯粹是给你自己回顾用的记录。

### Home 对话列表
- 每条对话左滑会露出一个"删除"按钮——不是滑到底直接删，还要点一下+二次确认才真的删除，避免误滑丢了一段对话。同一时间只会露出一行，滑开新的一行会把之前露出的收回去。

### AI 对话室内的常规操作
- 支持流式输出、停止生成、复制消息。
- 长按/点击用户消息的"回溯编辑"：会把这条之后的消息封存（不是删除，可以在"显示已封存消息"里找回），并把原文放回输入框方便你修改重发。
- AI 消息的"让他重说"：封存这条回复，重新生成一次。
- 按你的要求，界面里不再显示"AI 生成"角标——请自己留意：所有角色回复终究是 AI 生成的内容，不代表真实人物、不构成现实承诺。

### 记忆收藏
- 在对话里点消息下面的"☆ 收藏"，会把这条消息收进"记忆收藏"。
- 也可以在"收藏"标签页里直接"＋ 新建"，手动写一段想记录的文字，可以配一张照片（上传时会自动压缩，不会存手机相机原图；照片跟壁纸/头像一样不会存进备份文件）。
- 支持按标题/内容/标签搜索，来自对话的收藏可以"跳转原消息"；右上角可以切换成"星空视图"，每条记忆是一颗点亮的星星。

### 能量波动（心情颜色）
- 在"心情"标签页点"＋ 记录此刻"，用纯色板自己选一个颜色，再给它起个自定义标签（比如"平和"/"有点累"），可以加一句备注。
- 一天可以记录很多次。
- "日"视图会把当天所有记录画成一条颜色渐变带；"周/月/年"视图是颜色热力图。多条颜色之间是柔和过渡的渐变（色标打在每段中点，让相邻颜色自然融合），不再是生硬拼接的色块，点某一天可以跳回那天的详细记录。

### 日历备注
- 底部导航第 5 个图标（日历），是很轻量的按天自由文字备注，不是完整日程管理——没有分类、没有重复规则、没有提醒推送，就是"点一天，写一句话"（比如例假第一天、吃药提醒，或任何想记的事）。
- 点日历格子里的某一天，弹窗里能加备注、也能删除当天已有的备注，格子上会有一个小圆点标记这天写过东西。
- 页面下方"近期备注"会列出今天及以后最近几条备注，方便一眼看到快到的事。

### 静默同频
- 屏幕右下角、悬浮在底部导航上方的一个小小心跳线图标，任何页面都能看到，点一下进入一分钟的全屏安静模式。
- 没有文字、没有输入框：背景跟随当前主题（白金/黑银），中间是一枚缓慢自转的黑白光环（太极意象，直接用当前主题的强调色/表层色撑开，不引入新配色），光环正中是一颗会转动、若隐若现闪烁的星芒十字；外层光晕按接近静息心率的双拍节奏（约每 1.1 秒一拍）明暗起伏，没有用真实心跳录音，用这个节奏本身代替"心跳"。
- 计时不显示在屏幕上，满 60 秒会自动淡出；中途轻点屏幕也可以随时提前结束，不会强留人在里面。

## 关闭所有 AI，只用本地记录功能

去"更多 → 工作台设置"，取消勾选"启用 AI 对话功能"（角色主动消息也有单独的总开关，同样默认关闭）。记忆收藏、心情能量波动这两个功能完全不依赖网络或 API，随时都能正常使用、统计和备份。

## 故障排查

| 现象 | 可能原因 |
| --- | --- |
| 发消息一直显示"网络请求失败" | 断网，或该服务商禁止浏览器直连（CORS），需要自建 Relay |
| 提示 401 | API Key 错误或过期 |
| 提示 403 | 密钥没权限，或该服务商禁止浏览器直连 |
| 提示 404 | Base URL / 模型名 填错了 |
| 提示 429 | 触发限流，或者账户余额/配额不够 |
| 换了浏览器/手机后数据没了 | 本机模式的固有限制，请用备份 JSON 文件恢复 |
| "持久化存储权限"显示未获得 | 部分浏览器/隐私模式不支持或需要用户交互后才会授予，属正常现象，不影响当前使用，只是意味着浏览器在设备空间紧张时更可能清理数据——请勤备份 |
| 角色主动消息一直没收到 | 检查：总开关和该角色的模式是否都打开了、是否在安静时段内、冷却时间/每日上限是否用完、以及——最重要的——你有没有把 App 完全关闭。没有后台推送是设计如此，不是 bug |
| 自定义协议怎么套都不对 | 先用官方 Postman/curl 示例确认接口本身能通，再对照请求体模板和响应文本路径一个个字段核对；如果对方接口需要签名之类的动态计算，这套声明式模板做不到，需要自己写后端转发 |

## 视觉风格

整体是玻璃拟态（半透明卡片 + 模糊 + 饱和度提升 + 微光边框 + 顶部高光内嵌阴影，"液态玻璃"质感），中文用思源宋体（Noto Serif SC）、少量点缀用花体 Pinyon Script（都通过 Google Fonts 加载，首次需要联网，之后浏览器会缓存）。背景是几团缓慢漂浮的柔光光斑，对话气泡是更清透的磨砂玻璃质感，不再显示"AI 生成"角标，同一发言方连续消息会像聊天软件一样"粘"成一组（只有最后一条保留完整圆角），消息两侧带圆形头像——上传了自定义头像图片就显示图片，没有就显示名字第一个字。取消了顶部的工作台名称横幅，对话列表标题直接叫"Home"，右上角是一个玫瑰线稿图标（点进去是 AI 资料库，跟"更多"里的入口是同一个页面）。底部导航是悬浮的圆角玻璃胶囊条，五个图标不带文字（只有隐藏的英文提示：Memory / Mood / Home / Calendar / Settings），用的是带纹理笔触的月相插画素材（`icons/nav-*.png`），不是线稿 SVG——用 `mask-image` 取形状、颜色照样跟随主题的 `currentColor` 走，选中态和居中的 Home 高亮不用额外写着色逻辑。五个图标从左到右是一条完整的月相弧线：残月（收藏）→凸月（心情）→日月同辉（Home，居中且比其他四个更大、始终用强调色悬浮在胶囊上方）→凸月（日历）→残月（更多），两侧对称。AI 资料库不占底部导航位置，从"更多"列表点进去。

"更多"页是一整块星野壁纸抽屉：canvas 画的星空/月晕背景（黑银主题）或中性铂金晨光背景（白金主题，绝不引入暖黄色调），顶部是花体签名区（工作台名 + "Star Chronicle" + "自 XX 月 XX 日 · 第 N 天"），下面盖一块真正半透明的液态玻璃卡片列表——每一行图标 + 中文名 + 小写英文点题（比如"Dress the light"）+ 箭头，点开才是详细设置的独立整页，而不是把所有表单摊平堆在一屏里。

字段比较多的表单（API 连接、资料库编辑、对话设置）从原来的居中弹窗改成了从右侧滑入的整页抽屉：带返回按钮的独立页面，内容可以舒服地滚动，不再是那种因为字段太多而不得不在弹窗里加滚动条、显得局促截断的感觉。字段不多的小表单（心情记录、每日链接状态等）仍然是屏幕正中的居中卡片弹窗。点按任意位置都会有一圈（比较克制、不会很大的）水波光晕扩散开——白金/黑银两套底色下都能看清楚，光晕颜色默认跟随强调色，也可以在"更多 → 工作台设置"里自定义成任意颜色，只影响这一处点击光晕，不会改动其他任何 UI 元素的配色。

开屏是锁屏风格：顶部是日期（小字）+ 真实当前时间（大字，每分钟自动刷新），中间是花体英文 "Welcome Home"（Pinyon Script），背景默认是当前主题的纯色（黑银主题=黑色、白金主题=白色），也可以在"更多 → 外观·自定义壁纸"里分别给两套主题上传一张自己的照片当开屏背景（轻度模糊压暗当氛围衬底，能看出照片本身的色彩和轮廓，不是纯粹变暗糊成一片；不会盖住文字）；用了自定义照片或黑银主题时，背景上还会有几道带柔光头部的流星划过（头亮尾淡带一点锥形光迹）。不是定时器自动跳走——底部有一条横杠和"向上轻滑以进入"的提示，手指从横杠往上一划才真正进入（点击屏幕任意位置、键盘 ↑/空格 也能进入），不阻塞真正的数据加载，`App.boot()` 在它下面并行执行。`prefers-reduced-motion` 偏好下不强制要求手势，短暂停留后自动进入。空状态不再有装饰性插画，只保留"还没有对话"这类简洁文字提示。

**配色**：底色是中性的黑白灰极简风格（不再是暖金/香槟色调），只在"点按光辉"和"自定义壁纸"这两处允许有颜色，在"更多 → 工作台设置"里切换白金/黑银两套底色。**自定义壁纸**：白金和黑银可以分别上传一张自己的照片当背景，毛玻璃卡片盖在照片上面（真正的"液态玻璃"效果），不设置就还是原来的中性灰白/近黑背景+呼吸感光斑；壁纸图片不会存进备份文件，换设备后需要重新上传；上传时会先压缩到长边 1600px 再存（原图直接存手机相机照片容易在部分浏览器上因为存储配额悄悄失败），失败会有明确提示而不是假装成功。想恢复默认背景，在同一页面点"清除"即可。设了壁纸后"更多"页自己的星野背景画布会让位——不再画不透明的底色，只留星星/月晕这些本来就是半透明的装饰叠在壁纸上面，壁纸才能真正露出来。

**自定义头像**："更多 → 头像"这一个页面就能同时设置"你自己"和每一张"对方角色卡"的头像（角色卡列表直接列在这个页面里，不用再跑去 AI 资料库找），会显示在对应发言方的每条消息旁边、以及对话列表、资料库卡片上——同一张角色卡在所有绑定它的对话里共用同一个头像。没上传就还是原来的"名字第一个字"圆形占位。跟壁纸一样，头像图片不会存进备份文件，换设备后需要重新上传；上传时会先压缩到长边 500px 左右再存，避免手机相机原图太大导致保存失败。

**弹窗改用自制组件**：所有需要用户确认的删除/覆盖操作，以及提示性弹窗，都换成了跟整体视觉一致的玻璃弹窗（`js/ui-dialog.js`），不再依赖浏览器原生的 `confirm()`/`alert()`——原生弹窗在预览这类沙盒化的 iframe 环境里可能被静默拦截，点了按钮却没有任何反应。

## 技术说明（给开发者）

- 纯静态 HTML/CSS/JS，无构建步骤、无框架依赖。
- 数据层：IndexedDB，固定数据库名 `shiguang-db`，版本化 schema（当前 v4），见 `js/db.js`。升级只新增表，不删改已有表。
- 图片存储：`js/db.js` 的 `blobToStorable`/`storableToBlob` 是所有图片（壁纸/开屏背景/头像/收藏照片）存取的统一底层——Safari 部分版本上把 `canvas.toBlob()` 刚生成的 Blob 直接存进 IndexedDB 会抛 `Error preparing Blob/File data to be stored in object store`（WebKit 已知问题），所以存之前先转成 `ArrayBuffer` 包一层 `{__blob:true, buf, type}`，读出来时再拼回 Blob；同时兼容这次修复之前存的裸 Blob 旧数据。
- AI 供应商适配：`js/ai.js`，支持 OpenAI 兼容协议、Anthropic Messages API、Gemini 原生 REST，以及一套声明式的自定义协议映射（模板字符串替换 + 响应路径提取，不执行任意代码）。
- `js/resources.js`：第 6 部分五区资料库。`js/memory.js`：第 8 部分独立长记忆。`js/proactive.js`：第 9 部分角色主动消息。`js/linkstatus.js`：第 5 部分每日链接状态。
- `js/pages.js`：字段多的表单用的整页抽屉容器（`Pages.open/close`），从右侧滑入、带返回按钮，独立于居中弹窗（`.modal-overlay`）之外的另一套导航方式。
- `js/ui-dialog.js`：`UIDialog.confirm/alert`，Promise 化的自制确认/提示弹窗，替代原生 `confirm()`/`alert()`（后者在沙盒化预览环境里可能被静默拦截）。
- `js/wallpaper.js`：自定义壁纸，图片以 Blob 形式直接存进 `settings` 表（IndexedDB 原生支持 Blob），用 `URL.createObjectURL` 渲染，不进 JSON 备份。
- `js/avatars.js`：自定义头像，跟壁纸走一样的 Blob 存储模式（键名 `userAvatar` / `charAvatar:<资源id>`），同样不进 JSON 备份；因为聊天消息列表是同步拼模板，用 `Avatars.preload()` 提前批量转好 object URL 存进内存缓存，模板渲染时直接读缓存，不逐条 await。
- PWA：`manifest.json` + `sw.js`（只缓存本站资源即 app shell，不缓存 AI 接口响应）。
- 全部功能只在浏览器本地运行，没有任何服务端组件，不上传数据。
